# UI QA notes

本轮只验证和收敛前端表现，业务逻辑、IPC 和引擎通信保持不变。以下项目是测试/静态审查中确认、但没有在本轮改动业务逻辑的问题，供后续单独排期：

| 区域 | 现象 | 影响 | 状态 |
| --- | --- | --- | --- |
| Git 改动列表 | 文件行和目录节点主要依靠鼠标点击，部分可点击 `div` 没有完整键盘语义 | 键盘用户不能用 Enter/Space 完成和鼠标相同的选择/展开操作 | 待单独修复交互语义 |
| Git / 聊天操作条 | 部分次要动作原先只在 hover 时出现 | 触控或键盘用户不容易发现操作入口 | 本轮已补充 `:focus-within` 可见状态；交互语义仍待单独修复 |
| 聊天文件摘要 | 文件摘要区域存在嵌套交互元素结构 | 屏幕阅读器和键盘焦点顺序可能不稳定 | 待单独修复 DOM 语义 |
| 终端 | 沙箱环境无法启动 `node-pty` 的 conpty | 终端真机交互无法在当前环境完整验证 | 环境能力限制，未改业务逻辑 |
| 资源管理器 E2E | 全量回归中「选中行按焦点降级」与「拖拽悬停自动展开」在等待 `D:\\dev\\aether-code` 树节点时超时；工作台专项其余资源树、虚拟滚动、编辑器标签用例通过 | 两条用例无法在本轮运行环境完成验证，未观察到由样式层引起的渲染报错 | 待单独复跑；与 `.e2e-tmp` 工作区状态相关 |
| MCP 设置 E2E | `mcp-ui.spec.ts` 13 条中 12 条通过；错误配置恢复用例收到 Windows `Get-CimInstance Win32_Process` 权限错误文本，未收到预期的退出码文案 | 测试环境的进程诊断权限替换了引擎原始错误，不代表设置页面样式或 MCP CRUD 逻辑失败 | 环境限制，已保留原始失败上下文 |

已通过的专项 UI 回归用例：聊天文件卡片/任务托盘 4/4，改动面板长列表 1/1，窄屏设置/终端 2/2，自定义强调色 15/15，知识库与 MCP 设置 12/13（其中 1 条为环境权限差异）。此前聊天/窄屏/变更面板 10/10、Git 工作区/变更网络 12/12、设置 CRUD 与设置注册表 7/7 也保持通过。

完整 E2E（1135 条）结果：1084 passed、13 skipped、28 did not run、10 failed。失败集中在内置浏览器用例的 Electron 页面提前关闭、`about:blank` 加载失败、`.e2e-tmp` 清理 `EPERM`，以及两条资源树等待工作区节点超时；另有 1 个 MCP 错误恢复断言被 Windows `Get-CimInstance` 权限错误文本替代。它们属于当前测试环境/运行时诊断差异，未修改业务逻辑；聊天、主题、设置、知识库、编辑器、Git、终端和大多数资源树用例均继续通过。

本次回归修复后的专项验收：`e2e/settings-responsive-layout.spec.ts` **3/3 passed**（单 worker）。它在 940×640、1280×800、1600×1000 下逐个切换 18 个设置分区，检查正文没有横向溢出；模型/安全页额外验证长名称与长 URL，记忆页额外验证搜索框和类型筛选框高度。`e2e/compact-panel-layout.spec.ts` **2/2 passed**。

任务托盘的底部进度指示器已改为 sticky footer，任务列表滚动后仍保留进度上下文；托盘滚动条使用统一的 5px WebKit 轨道与令牌颜色。
