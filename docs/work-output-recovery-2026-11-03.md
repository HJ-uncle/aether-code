# Work 输出上限与自动恢复修复

## 真实原因

2026-11-03 的围棋任务在 `deepseek-v4.1-flash-1017` 上失败，根运行记录为 `OUTPUT_LIMIT / output_limit`。只读历史显示服务端使用 Anthropic 协议，连续返回 `max_tokens`；被截断的段落只有思考内容，没有完整工具或正文。

该轮输入约 20,704 tokens，配置上下文为 268,000。引擎原先给 general/Work 固定分配 8,192 输出 tokens，恢复时最多 16,384；工具交换后又回到 8,192。再次截断时，“只恢复一次”的判断直接结束任务。此次不是上下文容量耗尽，也没有成功写入围棋项目文件。

## 修改

- 主生成请求没有显式 `maxOutputTokens` 时，Work/general 和 Code 都使用准入后剩余的上下文容量。移除默认 8,192 和恢复 16,384 的输出限制。
- 删除纯思考截断只能恢复一次的限制。每次恢复均回到正常循环，执行自动压缩、取消、显式迭代与预算检查。
- 输出准入预留量与实际输出容量分开计算，避免将剩余上下文全部算进预算准入而过早进入总结。有限累计预算仍限制真实请求预留。
- 保持工具权限、用户思考设置、供应商协议限制。被截断的工具参数不会执行；只执行之后完整生成的工具调用。
- Work 错误卡读取根运行的错误码和停止原因，区分输出截断与普通响应未完成；诊断保留原始英文及运行 ID。重试依然绑定原指令并保留新草稿。

自动压缩负责输入上下文，不能取消模型服务自身的单次输出限制；服务端仍返回长度截断时，由引擎安全续接。历史失败记录不会被改成成功，已失败任务需要重新发起。
