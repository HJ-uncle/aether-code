# 会话交付文件链接与资源树同步修复

日期：2026-10-08。

## 原因与真实文件核对

引擎生成的 `/api/v1/workspace/file/download?sessionId=…&path=index.html` 是下载协议地址。旧的 Markdown 链接判断只检查字符串结尾的扩展名，因此把它当成本机文件路径。编辑器随后尝试读取工作区之外的 `/api/v1/…`，出现用户截图中的 `download?...` 标签和权限错误。

本次只读核对确认 `D:\trust-test\index.html` 实际存在，大小 28,619 字节，与会话工具写入记录相符。工作区访问限制是正确行为；错误在于链接协议被误判。同时，资源树本地模式没有自动刷新引擎及终端直接写入的文件，造成文件已存在但目录仍显示为空。

## 修复范围

- 在普通文件识别之前解析准确的引擎下载端点；提取所属会话和相对路径。
- 本地文件按消息所属运行的工作区打开；远端文件使用已有的认证、绑定会话文件服务。
- 中文、嵌套目录、空格及 `%/#/+` 文件名只解码一次；无效、越界或跨会话参数给出错误提示。
- 本地资源树也监听工具事件，并对当前可见且已加载的目录进行有节制的轮询；切换工作区和隐藏侧栏时调整刷新生命周期。
- 修复远端历史恢复的初始化竞争：会话 ID 统一由 AppProvider 恢复或创建，聊天组件不再在渲染时自行生成 ID 覆盖远端选择。
- 修改模型、思考等级等普通设置时保留当前远端会话；等待设置响应期间如果引擎已切换，旧请求不能改写新来源的会话选择。
- 没有放宽工作区授权，也没有将引擎下载地址交给外部浏览器处理。

## 使用与边界

已经打开的旧 `download?...` 错误标签可以关闭，再点击消息中的文件链接。该越界错误标签不会恢复到重载后的工作区。运行中的旧程序需要加载新构建才能生效。

当前 HTML 预览会清理脚本，所以“能打开源码和静态预览”不等于“可以运行交互网页”；后者由另行调研的嵌入浏览器方案解决。

子代理默认交付沿用父会话上下文。若子代理自行拼接其 child session 下载地址，目前会保守拒绝；支持这种链接需要验证真实父子关系并区分产物会话与工作区绑定会话，不能通过放开任意跨会话读取解决。
