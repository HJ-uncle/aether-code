# Work 首版实现与验收

日期：2026-10-11。对应此前确认的独立 Work 首页、工作中布局和模式切换方案。

## 打开与使用

运行客户端后，在左上角选择 **Work 办公**。使用当前已配置并就绪的引擎和模型，填写任务目标，点击“开始任务”（Ctrl / Cmd + Enter）。本地任务可选择独立工作目录并添加资料；远端任务使用服务端独立沙箱，不继承 Code 的项目目录。

## 本版已实现

| 维度 | 行为 |
| --- | --- |
| 外壳 | Code / Work 模式切换、记忆上次模式、220ms 内容过渡、键盘左右切换、减少动态效果适配；标题栏保持 46px |
| 布局 | 五项导航、首页模板与目标输入、最近任务搜索和筛选；工作中对话与工作区并排，可调整比例、收起导航和工作区 |
| 响应式 | 窄窗口先压缩导航，940px 使用对话 / 工作区切页；统一深浅色与强调色令牌 |
| 任务 | 独立 Work 会话、真实 HTTP / SSE 执行、停止、等待补充及回答、错误反馈、历史恢复与加载失败重试 |
| 连续性 | 切模式不销毁 Code 编辑器、终端或 Work 对话；各自草稿保留，Work 任务按引擎来源隔离 |
| 执行展示 | 单层步骤清单，状态在右；工具参数、结果与错误在“活动”；上滚暂停自动跟随，回到底部恢复 |
| 资料与成果 | 添加文件、依据实际写文件回执预览成果、区分草稿与已生成；文件及选中文字可加入草稿，不自动发送 |
| 管理入口 | 项目按任务目录分组；引擎、模型、技能、MCP 复用统一设置，并可在 Work 内打开设置 |
| 隔离 | Code 历史排除 Work 会话；双模式命令缓存分别持有；隐藏 Code 时禁用其命令入口；原生浏览器随模式隐藏与恢复 |

## 明确边界

- 这是客户端首版，仍复用当前引擎的 **Code 工具配置**；未新增引擎级 `work` profile，未声称完成办公专属权限或工具范围。
- “自动化”和任务内“浏览器接管”明确展示待接入状态。已有浏览器仍在 Code 可用。
- 成果预览来自文件写入回执，不把 AI 文本中声称生成的文件当作真实成果；“已生成”不等于质量检查通过。
- 本版成果页展示当前任务成果，Office 原生预览、完整历史版本管理、成果库、团队项目与业务应用连接尚未实现。
- 切到其他 Work 任务时，旧任务在服务端继续，重新打开后恢复最新状态；尚未增加所有后台任务同时订阅的全局任务调度器。
- Work 使用可控的本地 HTTP / SSE 测试引擎验证交互协议；这不等于验证所有外部模型的真实推理质量。
