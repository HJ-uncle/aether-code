## 问题与完成的调整

| 用户操作 | 原有问题 | 当前行为 |
| --- | --- | --- |
| 运行中追加消息 | Code 按 Enter 入队，点击主按钮却停止任务 | 发送与停止使用独立按钮；点击和 Enter 都可排到下一轮 |
| 点击停止 | 没有可观察的等待状态，部分调用吞掉失败；后台任务只凭接口返回就标停止 | 停止期间禁用重复操作；按 session/run 精确取消，读取权威状态后确认。未确认时保留队列和实际运行状态 |
| 新建会话 | Code 会主动取消旧会话运行 | 仅切换视图；已接收任务继续由引擎执行，切回读取真实进度 |
| 多会话队列 | 队列未按会话隔离，B 完成可能发送 A 的待发消息 | 读取、发送、合并、编辑、删除、排序均限定当前会话。明确拒收的队列保持暂停，切走切回不会自动重投 |
| 发送被明确拒绝 | 主进程正常返回，历史恢复可能覆盖刚输入的消息与错误 | 发送前校验失败及明确 4xx 拒收贯穿 IPC 返回；保留失败消息，恢复原草稿、引用与已上传附件。已有新输入时显示“找回未发送内容”，追加恢复而不覆盖新输入 |
| 发送途中切会话 | 尚未真正发出的请求被取消后可能当作成功 | 派发前取消明确标为未发送；迟到拒收回原会话，旧引擎结果不能混入新连接 |
| 断线 | Code 与 Work 提示不同，旧运行状态可能被描述为仍在执行 | 共用简洁连接提示，明确“任务状态待确认”，诊断默认折叠，受阻时提供重新加载 |
| Work 添加资料 | 运行中按钮禁用，但粘贴、拖入仍可用 | 文件选择、粘贴、拖入采用同一规则；下一轮可添加资料，上传中、未就绪等状态提供一致反馈 |
| 正常取消 | 引擎可能输出 `[System Error: …]`，客户端又生成“已停止”的错误条 | 正常取消不生成模型错误正文或伪造错误提示；真实执行异常仍保留诊断 |

界面沿用现有系统字体、主题令牌、克制的按钮样式。按钮提供明确的可访问名称与忙碌状态。发送拒收原因留在失败消息旁，避免重复弹层遮住恢复后的输入。

## 状态边界

- HTTP 成功与任务成功分开处理。生产引擎也可能通过 HTTP 200 返回业务错误信封。
- 停止目标包含明确的 `sessionId` 与 `runId`；`cancelled:false` 可能代表任务已自然结束，不能直接显示“已停止”。
- SSE 的 `[DONE]` 表示当前连接结束，真实执行状态以运行快照为准。
- 5xx、断网与已经派发后取消观察连接都可能是结果未知，不自动恢复成可重投的请求，也不偷偷重新执行。
- 附件恢复复用已上传对象，不重新上传；跨会话、工作区、引擎或卸载后的旧恢复回调失效。

## 追加、停止与重试的定向补充

用户明确优先“运行中追加要求、停止或重试不顺”后，本次进一步修改客户端：

- Work 快速重试绑定具体任务、错误消息及其原始用户轮次，核对运行/对话身份；不再使用任务级内存失败缓存或当前草稿兜底。旧错误卡不再调用最新失败的重试入口。缺失原始请求时不发送。
- 重试独立于输入框：携带原指令、引用及原附件，保留后来写的草稿和新附件。连续失败、刷新后仍从对应原消息恢复，不会因一次失败的重试清除恢复依据。
- 最新停止/中断轮提供“编辑后继续”，失败轮提供“编辑后重试”；内容和附件带回输入框并聚焦，已有草稿按段保留，不自动发送或删除历史。
- Code“添加到对话”同样追加恢复正文、引用与已上传附件。共享合并函数保留引用位置，避免同名手输 @ 文本被误识别为引用；完全相同草稿不重复追加。
- Work 普通发送失败时读取实时草稿，避免较早的持久化状态覆盖刚输入的新内容；空输入恢复原文时也恢复引用元数据。
- 运行中追加文案明确“排到下一轮”，Work 待发条目区分暂停和等待上一轮成功。此次没有增加运行中立即插入指令的引擎协议。
