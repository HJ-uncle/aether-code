# Work 单击到底专项

## 修正

原来点击“回到底部”或“回到最新”会先设置跟随状态，并立即按旧 DOM 高度滚动。按钮依赖跟随状态而隐藏；随后消息窗口、离屏内容高度或运行状态栏发生布局变化时，滚动事件又可能取消跟随。

本次调整：

- 显式跳转通过独立请求触发 React 提交后的滚动，消息窗口未改变时也会执行。
- 按钮根据实际底部距离显示，保留 2px 的小数像素容差。
- 内容与视口尺寸变化由 ResizeObserver 校正底部位置。
- 程序滚动记录目标位置，布局事件不再直接取消跟随；用户向上滚动、键盘浏览、拖动滚动条仍能暂停。
- 返回最新时清除之前加载历史所保留的滚动锚点。

## 补充：到底后蓝条仍停在倒数第二轮

用户再次反馈双下箭头像是“下一条”后，发现上面的测试只检查了滚动位置，没有检查导航选中项。

`MessageNavRail.syncActive()` 取视口上方三分之一作为当前轮次的判定位置。最后一轮很短时，它可能已经完整显示在窗口底部，但判定位置仍落在上一轮，因此蓝条从第一条变成第二条，呈现“只到下一条”的错误反馈。

新增 `e2e/work-bottom-tail-anchor-ui.spec.ts`，三轮对话中前两轮较长、最后一轮很短。旧构建稳定复现：真实滚动距离已为 0，末轮可见，但第三条没有 `aria-current`，第二条仍被选中。该用例在旧构建失败。

修复为：实际到底且最后挂载锚点就是整场会话最后一轮时，直接选中末轮；较早历史窗口保留按位置判断，不能把局部窗口末尾当成整场末尾。

修复版新专项 **2/2 通过**：

1. 相同底部位置，第三条正确高亮，第二条取消高亮。
2. 192 条消息的早期显示窗口只挂载前 90 轮，局部底部正确高亮第 90 轮，不会误标尚未挂载的第 96 轮。

构建（含 node/web typecheck）通过；Electron 正常退出，无渲染或原生错误。旧版失败记录：`.e2e-tmp/work-tail-anchor-before/`；修复版截图与结果：`.e2e-tmp/work-tail-anchor-20261105-results/`。未执行旧 E2E 或导出测试。
