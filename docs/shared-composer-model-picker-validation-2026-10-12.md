# Code / Work 共享输入框与模型菜单验收

日期：2026-10-12。范围：本轮输入框统一、上下文用量、AI 润色位置和模型选择改动。

## 完成的体验

| 功能 | 验收结果 |
| --- | --- |
| 输入框 | Code、Work 首页、Work 任务页使用同一个 InputComposer，输入区、表面、底栏和发送/停止按钮共用组件与样式。 |
| AI 润色 | 两种模式都放在输入框右上角；处理中显示反馈；任务切换后的旧回复不能覆盖新草稿。 |
| 上下文用量 | Work 复用 Code 的用量环与详情卡，保留确认/估算、模型容量、压缩及动画语义；跨任务和模式隔离。 |
| 模型选择 | 两种模式统一为简洁下拉，显示配置名称；菜单包含添加模型、管理模型，错误时可重新加载。 |
| 默认模型 | 已确定的默认配置显示实际模型名称与来源，例如“模型名称 · 客户端默认”或“模型名称 · Agent 配置”。未知配置显示“跟随引擎配置”。 |
| 模型请求 | 历史数据库 ID 映射为 modelId；保留列表外会话模型；未知旧会话不借用客户端默认或实际回退模型。 |
| 窄窗口 | 输入框按自身宽度响应，而非只依赖整窗宽度；模型名截断，工具条保持对齐，润色按钮不覆盖输入和附件。 |
| 主题及键盘 | 深浅主题共用颜色令牌；下拉支持方向键、Enter、Esc 与焦点返回，模式切换关闭浮层。 |
| 加载恢复 | 历史加载和模型就绪分开，历史读取失败后可点击重新加载，恢复后待启动任务只发送一次。 |

“默认”代表跟随配置，不是额外的模型。在能够确认默认配置时显示其名称与来源；旧会话没有保存请求模型时，不猜测下一次请求应使用哪个客户端模型。

## 请求与布局验证要点

- 使用真实 Electron 窗口、IPC 和 HTTP/SSE 通道，受控服务端捕获实际请求。
- 模型选择后的 HTTP 请求使用 modelId，不使用数据库记录 ID。
- 恢复缺少模型或旧占位名称的会话时，即使客户端默认非空，也显示跟随引擎配置；主请求和无独立轻任务模型的润色请求均不注入 model。
- 明确选择客户端默认后，名称与来源跨刷新保留，润色请求使用对应模型。
- 管理模型直接打开模型设置页；添加模型打开实际表单。空模型列表也可以使用这两个入口。
- Code、Work 首页和任务页分别验证深/浅主题与 1440 / 940 窗口尺寸，检查表面、润色位置及工具条几何。四张最终布局截图已人工核对。
- Work 已确认用量 64k / 128k 显示 50%，详情准确，切换任务、Code 和刷新不串统计。

## 回归发现及处理

1. 同目录其他构建会重新生成 out/，曾使测试窗口刷新时找不到 renderer 文件。最后两轮使用已构建的独立副本，并核对复制前后 index.html 的 SHA256，避免并发构建污染测试。
2. 一轮发现历史失败后重新加载按钮被模型等待状态禁用。当前代码已分离 loading 与 modelReady；最终 27 条 Work 回归全部通过，包含失败重试。
