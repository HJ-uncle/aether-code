# Aether Work：工作中的布局与交互

日期：2026-10-11。

本方案补充 [Work 客户端布局建议](./work-layout-proposal-2026-10-11.md)。用户已确认左上角 Code / Work 切换和 Work 独立首页，本文件只细化任务执行、等待补充、查看成果以及继续修改时的布局。

本轮仅新增设计文档和由主任务维护的独立演示原型，不修改产品代码。原型中的任务、进度、Agent、成果与浏览器内容均为示例，**未接入真实任务或引擎**，不表示对应运行能力已经实现。

## 1. 从首页进入任务

左上角 Code / Work 位置不变，沿用“工作台、项目、成果、自动化、连接”五项导航。打开任务后，工作台主体进入“协作对话 + 工作区”，无需新增一级导航或第二套活动栏。

```text
┌──────────────── 固定标题栏：Aether · Code / Work ──────────────────┐
│ 主导航       │ 工作台 / 竞品分析报告             正在分析  停止  … │
│              ├───────────────────────┬────────────────────────────┤
│ 工作台       │ 协作对话              │ 成果  资料  浏览器  活动    │
│ 项目         │                       │                            │
│ 成果         │ 用户目标              │ 选中的报告 / 表格 / 网页    │
│ 自动化       │ 进度清单              │                            │
│ 连接         │ 简短进展与补充交互    │ 实际内容预览               │
│              │                       │                            │
│              │ 补充要求或调整方向    │ 文件版本 / 来源 / 检查状态 │
└──────────────┴───────────────────────┴────────────────────────────┘
```

右侧工作区以可查看的资料、网页和成果为依据出现。尚无相关内容时，不保留一整列空白占位；已有资料或正在使用浏览器的任务可以立即打开工作区。

## 2. 十二项执行态规则

### 2.1 固定任务头，状态在右

任务顶部保持一条标题栏：左侧为任务名及所属项目，右侧为当前状态、停止和更多操作。等待补充、连接中断、执行失败与正常运行使用明确中文文字，不能只靠颜色表示。

任务状态变化不再额外增加横幅层级。需要用户处理时，状态入口定位到对话中唯一的待处理对象。停止后显示真实执行回执；没有实现可恢复暂停前，不提供名义上的“暂停”按钮。

### 2.2 宽屏三栏，优先保证内容可读

宽屏使用导航、协作对话、工作区。原型起点可取约 220px 导航和 400–440px 对话，剩余宽度用于工作区；用户可以调整分栏、收起导航、最大化成果并恢复此前布局。

任务标题、两侧工具条、正文边距和底部操作区共用对齐基线。沿用现有主题令牌与公共组件，表面层级轻微区分，不形成左右两套配色，也不套用大量独立边框卡片。

### 2.3 对话只承载协作信息

对话展示用户目标、必要的 AI 进展、澄清问题、重要发现和结论。工具参数、请求日志、抓取全文与错误栈进入工作区“活动”，不让每次读文件、网页跳转或网络请求都占据大段会话。

重要问题仍需就地解释原因和下一步；隐藏原始日志不能让失败变成无反馈。

### 2.4 步骤只折叠一层

进度清单按“整理资料 → 交叉分析 → 编写报告 → 检查交付”呈现。整组可以收起一次，普通步骤不再嵌套第二层折叠。

每行左侧显示步骤名称，右侧稳定尾列显示“已完成、进行中、等待、失败”等状态。当前步骤默认可见；点击详情在工作区展示，不在原行继续展开多层。无法可靠计算时不显示百分比或预计完成时间。

### 2.5 子代理呈现分工，活动按需查看

并行研究可以以紧凑同级行展示“市场研究、产品对比、数据核验”，各行状态放在右侧。点击后在工作区查看对应产出、活动及问题，避免将多个 Agent 的完整工具日志插入主会话。

某个子代理等待、失败或结束，不直接等同于整个任务状态；任务头反映汇总状态，具体原因可定位到相关分工。

### 2.6 工作区围绕同一任务组织

工作区按需提供“成果、资料、浏览器、活动”。成果视图中再选择文件；来源、检查和版本属于所选对象的信息，不再增加常驻第四列。

文件预览优先获得阅读面积。资料和成果要区分原始输入与生成输出；不可预览、解析中或访问失败均有明确状态及处理入口。

### 2.7 部分成果可以提前看，但不抢焦点

报告草稿、整理后的表格等可用后即可预览，清楚标识“草稿、生成中、待检查、已完成”。任务仍在运行，不影响查看已生成部分。

首次产生可用成果可以提示打开；用户正在阅读资料、历史消息或浏览器时，仅更新计数和状态，不强行切换页签、重置滚动或将焦点移走。流式更新要保留阅读位置，避免每次刷新内容都滚回开头。

### 2.8 补充信息保持唯一交互位置

需要用户补充时，在对话中显示问题、选项或附件入口及提交动作；任务头的“等你补充”定位到该交互，不再创建第二份确认。

输入、选项和已选文件在切换工作区、模式或短暂断连后保留。局部等待时仍在执行的其他分工可以继续显示运行状态。执行中的补充输入必须说明是立即调整还是排队处理，依据真实引擎能力决定。

### 2.9 成果与资料可以添加到对话

选中文字、表格区域、文件、来源或错误时，提供“添加到对话”。输入区显示可移除的上下文标签，清楚标明来源对象与版本；引用范围可以查看。

针对成果继续修改时，明确显示“针对：报告 v2”等上下文，避免用户以为正在修改当前预览，实际却向另一文件或旧版本发出要求。引用动作不自动发送消息。

### 2.10 浏览器明确显示控制权

浏览器工作区展示实际页面、简短动作状态以及“接管、交还 AI”。用户接管期间，AI 停止操作该页面；交还后应重新获取页面状态，再继续后续动作。

网络、控制台和操作记录按需进入，同一时刻只保留一个主要检查视图。浏览器原生 surface 的隐藏、bounds 更新与模式动画需单独协调，不能假定普通 CSS 过渡能够控制它。

### 2.11 完成后继续工作，保留版本

完成消息提供关键结论、文件清单、检查结果和继续修改入口，成果正文留在工作区，不重复粘贴全文。生成完成、检查通过、业务写回成功是不同状态，按实际回执显示。

修改生成新版本，保留上一版本供对比、恢复或导出；继续修改仍属于原任务上下文，不重置成新空页面。新版本可用时提示查看，正在阅读旧版的用户不会被强制切走。

### 2.12 滚动、窄屏和动效保持连续

任务会话默认跟随最新内容；用户主动上滚后暂停跟随，提供“回到最新”及新内容提示。回到底部后恢复跟随。进度状态更新、子代理活动或右侧预览变化都不应强迫会话滚动。

左上模式切换沿用约 220ms 的整体过渡，固定标题栏不漂移，快速切换以最后一次选择为准。尊重减少动态效果设置；布局动画不重建任务连接、不终止后台执行、不抢焦点。

## 3. 原型视口与正式适配边界

为便于在聊天内联预览中检查工作态，本轮示例使用以下规则：

| 演示范围 | 原型行为 |
|---|---|
| 宽屏 | 导航 + 协作对话 + 工作区，支持查看成果与活动 |
| 约 1024px 内联视口 | 收起导航，主体约 44% 对话、56% 工作区 |
| 小于 760px 的示例视口 | 主体改为“对话 / 工作区”页签，保留两边草稿、选择与滚动位置 |

**这些是独立原型尺码与演示断点，不是正式产品阈值，也不是 Apple 对齐标准。** 正式客户端应依据字体缩放、侧栏宽度、当前内容以及两栏最小可读宽度决定并排或切换，不仅按窗口宽度写死。

现有桌面客户端最小窗口为 940×600；仍需检查此范围内的中文长标题、文件名、系统缩放、DPR、键盘焦点和拖动分栏。内联原型的小屏演示用于说明退化方式，不意味着本轮更改桌面窗口限制。

空间不足时优先收起导航，再切为单主内容；任务状态、停止、待处理计数必须可见且可键盘到达。底部输入不能遮挡正文最后一行或当前焦点，内容区不应产生意外横向滚动。

## 4. 建议原型演示链路

1. 打开“竞品分析报告”，查看资料整理与并行分析的紧凑状态。
2. 切到成果，预览生成中的报告或比较表。
3. 切到资料、浏览器或活动，验证新成果出现时不会抢回当前视图。
4. 进入“等你补充”，从唯一交互位置补充范围并继续。
5. 选中成果片段添加到对话，查看明确的成果版本上下文。
6. 查看完成态与版本选择，继续修改产生下一版。
7. 缩窄预览并切换 Code / Work，检查状态、草稿、滚动与视图选择保持连续。

以上链路用于审阅布局和交互意图；真实任务调度、子代理状态聚合、文件生成、浏览器控制权和版本持久化仍需后续产品实现及集成验证。
