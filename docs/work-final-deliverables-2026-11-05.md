# Work 本轮最终交付与成品图片

## 问题与范围

用户本次导出的记录中，截图脚本确实生成了四套主题及移动端图片，工具也读取过其中的图片；随后八张 `test/shots/*.png` 被作为临时文件删除，最后的助手正文没有图片链接。此前的过程图展示、浏览器视觉输入和按轮文件回执，都不能证明图片已经作为最终结果交付。

用户确认：回复和成果区只展示本轮最终交付物、成品图片；过程截图、测试日志、中间文件留在展开过程。

## 交付契约

- 模型通过 `deliver_files` 明确选择本轮交付物，既不扫描最后一张截图，也不根据文件夹名判断是否成品。每项可指定真实文件路径，或本轮成功工具的 `toolCallId` / `imageIndex`；重复登记替换完整清单。
- 引擎保存不可变资产副本。正式最终回复中的 `finalResult` 携带所属 session、turn、run、assistant、正文和资产清单。
- 已登记资产只有在对应根运行成功后才显示为成果。运行中、等待、失败、取消和中断不会把暂存内容冒充成品。
- 资产读取通过认证接口核对所属运行及清单；不再依赖原始工作区文件。下一轮改写同路径或清理临时文件不会改变旧轮已交付的字节。
- SSE、历史回放、快照及完整历史展示使用同一份交付身份；过期显示页不能覆盖新收到的结果，重复帧不会复制附件。

## 界面行为

- 最终正文按明确的结果字段展示，过程叙述留在过程。复制回复也只复制最终正文；完整导出仍保留原始过程证据。
- 本轮附件由显式清单驱动，成品图片直接显示并可放大；文件提供预览和导出入口。
- 成果工作区默认显示本轮明确交付。新一轮纯文字回复没有附件时，不回退到旧轮图片。
- 所有修改回执仍可从过程中的文件操作进入审查；不再把每一次文件改动都包装为最终成果。
- 旧历史没有明确交付清单时，不会自动把任意工具截图或写入回执晋升为成果。
- 带根运行身份的消息在最终清单到达前全部保留在过程，避免成功状态先到时短暂外显过程图片；旧轮无清单的内容仍可展开过程阅读。
- Work 的最终图片统一使用清单内保存的资产，正文 Markdown 不再绕过清单读取工作区图片。Code 模式继续使用原有 Markdown 图片展示，提示词按模式区分。
- PDF / Office 等附件按真实 MIME 和原始路径选择预览器，用户自定义无扩展名的展示名称不会改变预览格式。
