管理权限与能力授权

管理插件、授权插件能力、批准一次会话操作是三层不同的检查。启用账户认证的部署要求当前账户具有 admin 或 plugin-manager 角色，才能管理插件；关闭认证的本机部署允许本机身份管理。管理角色不会自动授予插件上述能力，能力开关也不会替代会话安全策略。

会话操作确认

通过会话中的 Agent 创建、修改、测试或发布插件时，默认会先展示操作确认。点击「完全访问并放行」后，当前操作继续执行，当前会话后续的操作确认自动通过；其他会话不受影响。切回标准模式或安全模式后，新的操作恢复对应模式的审批与限制。

需要补充内容或选择方案的提问仍需用户回答。完全访问不会替插件开启本页列出的权限，也不会跳过参数、角色和版本冲突检查；插件自行显示的交互对话框仍由插件决定。

会话与工作区由打开插件的入口绑定，不能通过业务参数指定另一个会话。context()、本插件的页面导航、声明工具和服务调用不单独申请权限；其中调用的平台能力仍需授权。

权限开关约束 $AE 平台接口。Node 工具是本机代码，开关不限制 Node 自身的系统权限；仅运行可信来源的 Node 插件。

插件管理的「权限 → Agent 工具」可按名称搜索并禁用工具，设置立即保存，升级版本仍保留。禁用在实际执行前复核；插件通过 disabledTools 只能追加禁用，不能覆盖用户选择。开发模式也支持独立的用户工具禁用设置。

插件 Agent 的内置范围固定为六类、35 个工具。其他 $AE 能力供插件代码直接调用，授权后也不会自动变成 Agent 工具。开发者显式配置的 MCP 和本插件自定义工具分别按对应授权执行。
