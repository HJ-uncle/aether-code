# Aether Work 客户端布局调研与设计建议

日期：2026-10-11。

本文件承接 [Work 模式功能调研](./work-mode-research-2026-10-11.md)，讨论客户端的信息架构、页面布局、模式切换和交互验收。用户已明确：左上角提供 Code / Work 切换，Work 采用符合其办公定位的全新排版，切换时可以增加过渡动画。

本轮只新增设计文档，不修改客户端或引擎代码。下文中的尺寸、时长、断点和组件方案均为 Aether 的设计建议，需通过原型验证；它们不是 Apple 对所有桌面应用规定的固定数值。

## 1. 调研依据与适用边界

### 1.1 当前界面的直接观察

用户截图中，Aether 采用活动栏、版本控制侧栏、聊天区、编辑器欢迎页的 IDE 布局。左上角品牌后是文件、编辑、转到等菜单。该结构服务于开发工作，但在尚无任务或成果时，会为办公用户展示多个空区和不相关入口。

Work 需要围绕“交代目标 → 补充资料 → 观察执行 → 查看成果 → 修改或复用”建立页面结构。模式入口放在品牌旁，可以让用户在进入工作之前看清当前工作环境。

### 1.2 网上来源

主代理本轮实际查阅了以下官方页面；Microsoft 部分还查看了概述页面内的真实首页截图，而非仅根据搜索摘要判断布局。

| 来源 | 可借鉴的原则或界面组织 | 本方案的应用 |
|---|---|---|
| [Apple HIG：Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) | 侧栏承担导航、分组与当前位置表达，内容保持主导 | 主导航限定为五类；导航与具体任务操作分开 |
| [Apple HIG：Motion](https://developer.apple.com/design/human-interface-guidelines/motion) | 动效帮助理解状态变化，并尊重减少动态效果等辅助使用偏好 | 固定外壳，内容短时过渡；提供立即切换路径 |
| [Microsoft Copilot Cowork 概述](https://learn.microsoft.com/microsoft-365/copilot/cowork/) | 首页以任务发起和工作管理为中心，自动化有独立入口；页面截图提供实际信息层级参考 | 首页突出任务输入及最近工作，自动化独立管理，避免沿用 IDE 空面板 |

竞品页面和截图用于研究公开呈现方式，本轮未操作或实测其完整客户端。不将官方页面中的所有能力推定为任意账户、平台或发布阶段都可使用。

## 2. 设计结论

采用“共用应用外壳、独立 Work 工作台、按需打开成果画布”。

共用部分包括品牌、模式入口、窗口控制、主题、账号、设置、通知和底层任务服务。Work 拥有自己的侧栏、首页、任务页面、成果页面与自动化页面。两种模式可复用消息、输入、文件引用和预览能力，但不以复制整份 IDE 页面作为实现方式。

布局遵循四条原则：

1. 用户的目标、资料和成果占据主要空间；未使用的面板不预先占位。
2. 全局导航最多五类；功能完整性通过任务内工具与次级页面体现。
3. 一处表达一个状态，同一组任务进度只有一层收起操作。
4. 标题、工具条、正文和列表在同一栅格上对齐，减少重复边框与卡片。

## 3. 左上角 Code / Work 切换

### 3.1 固定位置与外观

标题栏保持 **46px**。品牌后放置明确的两段选择控件：

```text
Aether   [ Code 开发 | Work 办公 ]   应用菜单 / 当前模式菜单      全局状态 / 账号 / 窗口控制
```

- 两项互斥选择，当前项使用轻量填充和清晰文字；不是无标签的 on/off 开关。
- 品牌、切换器、窗口控制在两种模式下位置不漂移；切换后不另增第二条模式工具栏。
- 菜单根据模式提供不同命令或可用状态。Work 不常驻展开 IDE 菜单横排，相关命令仍可从应用菜单、命令搜索或快捷键找到。
- 标题栏保留拖动区域；模式控件、菜单和窗口按钮属于可点击区，不响应窗口拖动。
- 中文界面保留 Code / Work 作为模式名称，辅以“开发 / 办公”说明；无需用户先理解技术概念。

46px 是结合 Aether 当前外壳的设计决策，不代表 Apple 的统一标题栏高度标准。

### 3.2 切换语义

切换模式只改变当前工作界面与默认新任务能力，不改变已存在任务的归属、目录、执行位置和权限快照。

- Code 与 Work 分别保存当前任务、项目、输入草稿、滚动位置和面板状态。
- 正在运行的任务继续运行；全局任务入口可看到另一模式中的进度和待处理事项。
- 返回原模式恢复原位置，不自动创建空会话，不清空附件或草稿。
- “在 Code 中打开文件”等显式动作可以跨模式定位；普通任务事件不自动切走当前界面。
- 旧引擎不支持 Work 时显示真实不可用原因与处理入口，不能仅切换外观后继续以 Code 能力运行。
- Work、执行位置和权限策略是独立维度；切换控件不承担安全模式开关职责。

## 4. 五项主导航

| 主导航 | 内容范围 | 次级组织 |
|---|---|---|
| 工作台 | 发起任务、继续最近工作、进行中、需要处理、任务历史 | 内容区按全部/进行中/需要处理/已完成筛选 |
| 项目 | 长期资料、项目指令、相关任务、团队成员和共享范围 | 概览/资料/任务；不要求绑定 Git |
| 成果 | 文档、表格、演示、研究报告、图表及版本 | 类型、来源项目、更新时间等筛选 |
| 自动化 | 定时、事件触发、试运行、运行记录、失败处理 | 自动化列表、详情、某次运行 |
| 连接 | 业务应用、知识源、已授权账户、健康状态 | 已连接/可添加；技能与模板作为次级能力入口 |

“新任务”是固定动作，不作为第六个导航。“需要处理”是工作台内可直达的筛选与计数，不再增加独立收件箱入口。账号和设置位于侧栏底部。

技能、专家和模板首先服务于“新任务”：用户可以按研究、写作、分析等结果选择模板。需要管理模板或能力来源时，再进入连接内的次级页面。避免把 Agent、MCP、技能、提示词、知识库全部变成同等级菜单。

搜索可以查找任务、项目、成果和操作，结果按类别分组。页面内搜索与全局命令搜索名称区分，快捷键遵守已有注册规则和系统平台约定。

## 5. 关键页面布局

### 5.1 Work 首页

```text
┌─────────────────── 固定标题栏与模式选择 ───────────────────────────┐
│ 侧栏                │ 工作台                                     │
│ 新任务 / 搜索       │ 开始一项工作                               │
│                     │ [描述目标，添加资料                    ]    │
│ 工作台              │ [附件 / 模板 / 资料范围            开始]    │
│ 项目                │                                            │
│ 成果                │ 需要你处理                                 │
│ 自动化              │ 任务名称                    原因 / 操作     │
│ 连接                │                                            │
│                     │ 最近任务                      筛选 / 搜索   │
│                     │ 任务名称                    状态 / 时间     │
│ 账号 / 设置         │ 任务名称                    状态 / 时间     │
└─────────────────────┴────────────────────────────────────────────┘
```

首页使用单一主内容区。输入框、待处理事项、最近任务共用对齐基线。初次使用可以展示少量可实际执行的任务示例；有真实工作后优先呈现用户内容。

没有待处理任务就不保留整块空位；没有历史时用一段简短说明引导开始。模板不做多屏卡片墙，不在首页展示所有连接器、所有项目和大量统计数字。

### 5.2 任务运行

默认采用“侧栏 + 任务主体”。顶部显示任务名、项目和右端状态/停止操作；正文展示目标、简洁进度、必要消息与结果；输入固定在任务主体底部。

- 状态在固定尾列展示，使用图标与中文文字，不能仅靠颜色区分。
- 计划步骤是单一紧凑列表；整组可以收起一次，普通步骤不再套第二层折叠。
- 当前运行步骤默认可见；工具参数、原始日志和错误栈通过“查看详情”进入检查视图。
- 新内容默认追随到底部；用户主动上滚后暂停追随，并提供“回到最新”。
- 用户待回复或待处理操作在原任务中有唯一位置；全局入口定位同一个待处理对象，不重复创建确认。
- 任务完成、业务写回与外发必须依据真实回执显示成功，不采用未经确认的乐观成功状态。

尚无可预览成果时不显示空白第三列。资料引用、模型或技能配置保持轻量入口，具体配置按需展开。

### 5.3 成果预览与继续修改

有成果后可在右侧打开可调宽的成果画布。宽窗口中，成果应获得足够阅读面积，而不是机械地与对话等分。用户可以最大化预览并恢复原分栏比例。

预览头统一包含成果名称、格式、版本和导出操作。正文优先展示实际成果，来源、检查状态、版本说明使用次级信息区。继续修改明确关联当前成果及版本。

资料和来源可通过次级页签访问，不再常驻第四列。可导出的成果同时支持明确的另存入口；拖出能力按平台与文件类型验证。

### 5.4 项目与资料

项目用于汇集长期资料、指令、相关任务与共享范围。项目页使用“概览 / 资料 / 任务”等内容页签，不增加与主导航竞争的第二条固定侧栏。

资料列表需要区分原始资料与生成成果，显示解析状态和来源；访问失败或格式不支持时就地说明。无项目任务应可直接开始，由系统管理任务目录。

### 5.5 自动化

列表优先显示名称、触发条件、下一次运行、最近结果和启停状态。点击后进入配置详情和逐次运行记录；某次运行包含步骤、输出、等待原因、失败及恢复动作。

新建以自然语言描述切入，并提供结构化检查：触发、资料、使用账户、执行位置、输出目标、重复执行策略。复杂工作流编辑器按需进入，不让所有用户先面对节点画布。

电脑离线、等待用户和实际执行失败应分别表达。试运行和启用是不同动作，启停自动化不应被误解为取消当前运行。

### 5.6 连接

将“已连接”与“可添加”分区。主要呈现应用名称、业务账户、可用范围和连接状态；过期、失效、缺权限等问题就地处理。

MCP 服务地址、协议、技术日志放入高级详情。连接完成不等于授权全部业务动作，应显示实际范围。技能、模板与知识源管理作为连接内次级页面，避免扩张主导航。

## 6. 视觉栅格、组件与窄窗口规则

### 6.1 对齐与密度

| 对象 | 建议规则 |
|---|---|
| 标题栏 | 保持 46px，不因 Work 切换缩小或增加整层工具栏 |
| 侧栏 | 初始约 220–240 CSS px，允许调整；折叠后主内容获得空间 |
| 内容边距 | 常规左右 24px；同页标题、工具条和列表首列共用基线 |
| 间距 | 控件常用 8px，区块常用 24px；依据内容层级调整 |
| 文字 | 正文建议 14–15px，说明 12–13px；优先系统与中文字体回退 |
| 列表 | 标题伸缩，状态/时间/菜单使用稳定尾列；长名称省略并可查看全文 |
| 表面与边框 | 使用现有令牌表达表面层级；避免边框套边框、每行都独立成卡 |
| 主题 | 深浅色及强调色共同支持；正文保持足够对比，不大面积纯白或过暗灰色 |

这些数值是原型起点，需要在真实窗口、中文长文本、缩放和不同 DPR 下检查，不能直接由截图物理像素推导 CSS 尺寸。

### 6.2 公共组件建议

优先审查并复用现有公共组件，再补齐缺失能力：

- 模式分段选择、导航项、页面标题与工具条。
- 搜索与筛选、列表行、状态标记、空状态和错误状态。
- 单层任务进度、待处理动作区、可调整分栏。
- 成果预览头、版本选择、来源引用和运行详情。
- 按钮、弹出菜单、对话框、焦点样式和提示反馈。

公共组件统一尺寸、对齐和行为；消息与任务数据服务尽量复用。不能为共享外观而强迫 Work 继续承载 Git、LSP、终端等默认 IDE 布局。

所有正式样式继续由 `src/renderer/src/assets/tokens.css` 提供颜色令牌，新增令牌需同时定义深色和浅色。组件中不得另写一套固定颜色。

### 6.3 窄窗口优先级

布局以可用内容宽度决定，不能只按某一截图尺寸写死断点：

1. 当前窗口最小尺寸为 940×600，应将其作为首轮桌面验收下限；主体能够同时保证约 400px 对话和约 480px 成果时，允许并排预览。
2. 空间不足时改为“对话 / 成果”内容切换，两侧状态与滚动位置保留。
3. 再窄时侧栏收为可打开抽屉，优先保留主任务。
4. 次要元数据进入详情；当前状态、停止和用户待处理动作仍可见、可通过键盘到达。
5. 操作区不能覆盖输入、焦点或正文最后一行；长文件名、中文按钮和缩放后不能产生无意横向滚动。

## 7. 模式切换动画规范

推荐总时长 **220ms**；模式选择底板 **160ms**；主内容位移最多 **6px**。这些数值是本项目的动效建议，不是 Apple 官方固定要求。

### 7.1 视觉过程

- 标题栏、品牌、模式选择器和窗口控制保持静止，形成空间锚点。
- 选中底板使用轻量过渡，主内容同步淡出/淡入并带最多 6px 位移。
- 正反切换可采用相反的小位移表达方向；不做数百像素整屏横滑、缩放窗口、弹簧反弹或大面积模糊。
- 220ms 是整个切换的总时长，不能前后各 220ms 叠加延迟。
- 首次加载显示目的页面的占位内容，不延长动画掩盖请求；失败提供重试和返回入口。

### 7.2 状态正确性

- 最后一次模式选择生效。快速重复点击时取消或替换旧动画，不能堆积待播放动画。
- 模式语义与活动页面立即更新；不能依赖 `transitionend` 或 `animationend` 才提交正确状态。
- 动画过程中只有活动页面接受输入；旧界面若用于退场画面，应退出辅助技术树并不可交互，避免双焦点、双快捷键和重复提交。
- 动画中断、窗口缩放、主题变化或页面卸载后都要清理临时样式，不能留下不可点击遮罩。
- 不为动画重建运行中的任务连接或取消任务，不将布局切换与引擎执行绑定。

### 7.3 辅助使用与焦点

- `prefers-reduced-motion: reduce` 下立即切换，不位移、不弹性过渡。
- 用户在模式控件上操作时焦点留在控件；可简短宣告“已切换到 Work”，下一次 Tab 进入新页面。
- 不强行抢焦点到输入框，也不把焦点留在已经隐藏的旧页面。
- 支持键盘选择并有可见焦点；选择器应使用正确的互斥选择语义，不以普通 on/off switch 冒充。

## 8. 客户端架构接入约束

源码只读核对显示，当前工作台是固定 IDE 骨架。建议拆分为共享的 `AppShell`、保留开发体验的 `CodeWorkbench` 和新的 `WorkWorkbench`。这是后续实现方向，本轮尚未创建这些组件。

| 已观察的现状 | 对布局和实现的约束 |
|---|---|
| [Workbench.tsx](../src/renderer/src/workbench/Workbench.tsx) 固定组合活动栏、侧栏、主区、底部面板和聊天区 | Work 需独立布局组件；任务与引擎服务置于共享生命周期，不随页面动画重建 |
| [MenuBar.tsx](../src/renderer/src/workbench/MenuBar.tsx) 的品牌后紧接菜单 | 模式选择器可在两者间接入；共享标题栏不等于共享全部 IDE 工具按钮 |
| [tokens.css](../src/renderer/src/assets/tokens.css) 已定义 `--titlebar-h: 46px` | 沿用既有高度和主题令牌，保持两种模式视觉一致 |
| [layout-state.ts](../src/renderer/src/core/platform/layout-state.ts) 使用 `aether.ide.layout` 保存布局 | 需按模式记忆布局，兼容现有 Code 布局数据，避免 Work 覆盖编辑器分栏习惯 |
| [主窗口配置](../src/main/index.ts) 设置最小宽高 940×600 | 原型和真实窗口以此为首轮下限；不能把手机式断点直接套到当前桌面配置 |
| [Workbench.tsx](../src/renderer/src/workbench/Workbench.tsx) 已对底部面板采用 keep-alive | 切到 Work 时不能因卸载整个 Code 树而丢失终端 PTY 绑定、xterm 画面和会话；需保留生命周期或可靠重连方案 |
| [BrowserView.tsx](../src/renderer/src/contrib/browser/BrowserView.tsx) 将实际边界和可见性传给原生浏览器 | WebContentsView 是独立原生 surface，普通 CSS 透明度与位移动画不能控制该原生层 |

浏览器需要专门的模式切换协调：离开当前模式时明确隐藏原生 surface；目标模式布局稳定后重新测量 bounds，并按目标标签及会话归属恢复可见性。退场画面可以使用受控占位视觉，但不能让原生网页浮在旧位置，也不能同时接收两种模式的输入。模式隐藏不等于关闭浏览器标签或终止相关任务。

`WorkWorkbench` 不携带 Code 专属的终端、编辑器分栏等标题栏按钮。全局控件固定，模式内工具按所在页面提供，避免通过大量 CSS 隐藏形成生命周期和快捷键泄漏。

## 10. 验证标准

后续原型和实现须分别验证视觉可用性与运行行为。本轮尚未运行产品测试，不把设计文档视为验证通过。

### 10.1 布局与视觉

- 在宽、中、窄窗口及 125%/150% 缩放下检查标题栏与列表基线；状态列不因长标题漂移。
- 深色、浅色及不同强调色下，选中、焦点、悬停、禁用、错误和等待状态都能辨认。
- 左上角切换器在两模式位置一致；标题栏保持 46px；菜单变化不推挤模式控件或窗口控制。
- 无成果、单成果、多成果、长文件名、无历史、无连接和离线状态均有明确布局。
- Work 默认不显示版本控制、代码大纲等无关空面板；导航不超过五类。

### 10.2 任务与状态

- 切模式后草稿、附件、任务选中项和滚动位置恢复；运行中的任务不取消、不重复启动。
- 切换不改变旧任务的 profile、权限、目录或执行位置；并行的 Code/Work 任务互不串状态。
- 任务进度只有一层收起操作；状态在右侧稳定显示；用户上滚后不被持续强制拉到底部。
- 待处理入口能定位原任务；失败、等待设备、等待用户、已完成不可混为同一状态。
- 预览最大化和恢复保持比例；窄窗口“对话 / 成果”切换不丢上下文。
- Code 中正在运行的终端在切换后继续存在，返回时会话和画面保留；非活动模式快捷键不干扰当前模式。
- 打开原生浏览器后切换模式、调整窗口和缩放，网页不残留在旧位置；返回后 bounds、可见性及点击位置准确。

### 10.3 动效与辅助使用

- 连续快速切换至少 10 次后，最终模式与最后一次选择一致，无闪回、遮罩残留或重复事件。
- 减少动态效果开启时立即切换，功能与普通模式完全一致。
- 全部主要操作可仅用键盘完成；Tab 顺序与视觉顺序相符，焦点不落在隐藏内容或被固定区域遮挡。
- 动画期间调整窗口、切换主题或停止任务，最终布局与状态仍正确。
- 模式改变不影响现有快捷键上下文；隐藏模式的命令不能误处理当前输入。

### 10.4 实现阶段检查

涉及交互、IPC、引擎通信的实现应遵守仓库 AGENTS.md，执行 typecheck、build 和相应真实窗口 E2E。模式切换、任务状态保留、成果分栏、键盘焦点及窄窗口行为需要实际窗口证据，不能只用类型检查代替。

## 11. 不采用的布局与交互

- 仅把现有 IDE 栏目改名，继续保留活动栏、文件树、聊天、编辑器的固定四区结构。
- 将 18 个功能块各自变成一个主导航，或首页堆满所有模板、统计和连接器卡片。
- 永久显示等宽三栏，成果尚未生成就占据大块空区。
- 单个计划步骤、工具调用、子任务再分别嵌套多层折叠。
- 为紧凑而整体缩小标题栏、文字和点击目标；为高级感降低对比或大量使用透明模糊。
- 切模式同时改权限、切引擎或取消旧任务；靠动画结束事件才能完成真实状态切换。
