# 思考开关修复与验证

截图中 Off 仍出现思考的主要原因在引擎请求参数：前端已传递 `false`，但聊天路由只停止注入开启参数，没有发送关闭意图；部分适配器会自动恢复默认推理。对象形式的关闭配置还曾被真值判断误识别为开启。

本次将明确的 `thinkingEnabled` 意图贯穿聊天、重新生成、模型解析、子代理和收尾，由实际模型适配器翻译为对应协议参数。关闭配置不再被自动开启覆盖，兼容性重试不能静默丢弃关闭参数。修正了 DeepSeek V4.1 的能力识别。没有过滤模型实际返回的 reasoning 来伪装关闭成功。

界面文案说明：修改设置对下一次发送生效，当前运行沿用原设置。未知兼容模型没有通用关闭开关；只能避免引擎主动开启，不能保证供应商一定关闭推理。DeepSeek 网关采用项目既有关闭协议；这些验证没有调用真实供应商或用户远端服务。
