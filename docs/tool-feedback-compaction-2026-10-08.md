# 工具结果、历史压缩和后台命令展示修复

本次依据用户提供的五子棋执行报告与后台命令截图检查 Aether 客户端和引擎。没有修改用户的五子棋项目，也没有把报告中的“15 项通过”当成本次重新执行的测试。

## 已确认的问题

1. 截图中的 HTTP 服务曾成功启动，报告随后包含 Agent 主动调用 `cancel_command`。引擎保留 `cancelled` 和实际退出码是正确的，但客户端把统一 error 字段直接渲染为红色警告，造成“服务执行失败”的印象。
2. `microCompactToolResults` 原先将工具结果改成 `[tool result cleared]`。这个值同时被模型上下文和用户历史读取，因此上一轮补齐的报告输出在压缩后仍会丢失。
3. 手动压缩接口插入固定 assistant 回复“我已经为您完成了上下文压缩……”。这段维护文案并非模型对任务的回答。后台压缩也存在类似的固定 assistant 文案。无法仅凭本次报告证明第一次任务为什么停止，但固定文案的来源和污染对话的问题可以从代码确认。
4. `browser_click` 的运行时要求 ref、selector、x+y 三选一，模型可见 schema 原先未结构化表达互斥条件，错误也只有英文泛化提示。本次未取得失败调用的完整参数，不能确定具体是哪一种字段组合错误。
5. 上下文压缩按钮读取了错误层级的统计数据，可能把压缩后的 token 数显示成 0。

## 修改后的行为

- 后台命令主动停止显示中性的“已停止”；真实退出码、信号和原始原因保存在“停止详情”。失败和超时仍有错误提示，不伪装成退出码 0。
- 长命令默认两行，可完整展开；重载后的终态命令卡默认收起输出，运行中的输出保持可见。
- 微压缩保留展示原文，模型继续读取精简内容；展示原文从模型请求和 token 估算中剔除，避免“为保留日志反而把上下文再次撑满”。
- JSONL 读取可从原始行恢复旧版清除结果；新 SQLite 微压缩保留原文。旧 SQLite 已覆盖掉且没有留存的内容无法凭空恢复，客户端明确告知。
- 手动和后台压缩不再伪造 assistant 回复；有运行中或等待应答的任务时，手动维护压缩返回冲突，后台维护压缩跳过，不替用户停止任务。
- 点击工具提供互斥参数 schema、长度/坐标范围以及含字段位置的中文纠错提示；保留导航版本和定位保护。
- 压缩环读取真实 `stats`，无统计时不显示虚假的 0。
