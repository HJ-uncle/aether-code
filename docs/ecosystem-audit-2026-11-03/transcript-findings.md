# 围棋会话：工具与生态使用复盘

调研日期：2026-11-03。只读分析，未重放任务、调用模型或修改产品。

## 结论

这份记录证实了三件不同的事：模型有些调用违背了工具规则；浏览器执行环境确实有操作失败；遇到这些问题后，没有稳定完成“恢复环境—重试—取得真实验证证据”的流程。不能把全部问题归为模型不会用工具，也不能把执行故障当作多加一段提示词就能修复。

另一个从当前源码确认的产品缺口是：通过 `execute_cmd` 中的脚本写入文件，没有走文件工具的变更账本。这会影响 AI 产物管理和回滚的一致性。它不是这份导出记录独自能证明的数据库事实，依据详见 [引擎清单](engine-tools.md)。

## 应当形成的产品流程

1. 开始运行时，系统提供真实的会话能力快照：模式、平台、shell、工作区、可用工具、浏览器状态、产物格式和权限边界。
2. 在工具第一次使用时，提供最小可执行范式与约束；保留详细 schema 的按需查询入口。
3. 将“没执行”“执行失败”“执行成功但未验证”分别结构化返回，界面与模型使用相同状态。
4. 浏览器当前已实现 reveal＋5 秒 bounds ACK，以及新 native host 协议。应核验它们在隐藏/最小化窗口、非当前任务和截图表面不可用时为什么仍会失败，补齐可验证恢复与明确后续动作，避免重复四次同类点击。历史导出不证明当时运行的是当前版本。
5. 文件工具、Office 工具和命令写盘统一关联到 run、变更、产物；保证用户能审阅和回退。
6. 最终交付提供客户端可打开的文件或预览入口，并区分功能测试、交互测试、视觉测试。后台服务使用受管理 job 标识，不能只留下启动命令。

上述是调研建议，本轮没有实施。
