# Git 与资源管理器同步修复记录

日期：2026-10-08。

## 根因与修复

新账号的会话工作区位于引擎仓库的子目录。资源管理器读取这个空目录，而旧 Git 接口仅使用 `git -C`，Git 自动向上发现了引擎仓库的 `.git`，因此展示了引擎的分支和变更。这个错误也会影响写操作的仓库选择。

- 引擎现在仅在当前授权工作区内寻找仓库，显式指定校验后的 Git 目录和工作树；目录链接、worktree/common directory、共享对象库、继承的 Git 环境变量及本地克隆源/目标不能把操作引向工作区外。
- 空工作区返回“非 Git 仓库”。未跟踪文件 `??` 只出现在“更改”，不会错误地同时进入“暂存的更改”。
- 客户端按连接、账号、会话和目录隔离 Git 缓存，丢弃迟到响应，取消切换工作区前排队的写操作。
- Git 面板和资源管理器可见时静默检查外部文件变更；窗口隐藏时停止轮询，恢复可见时立即更新。没有变化时不通知界面，也不反复显示加载状态。
