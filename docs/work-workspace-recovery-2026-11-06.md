# Work 工作目录恢复与紧凑面板

## 已核实的原因

开发启动器每次生成独立的引擎构建目录，旧的开发环境未提供持久 `WORKSPACE_ROOT`。引擎默认 `./workspace` 因而跟随运行目录变化，而会话数据库保存在固定目录。未绑定项目的同一会话重启后会落到另一个 scratch 目录。

会话 `work-home-c3f411f9-9b81-4aa7-96e9-2c9b973a4786` 的 `gomoku.html` 仍位于 `2026-11-05T13-02-40-520Z-Uhwd0Z` 构建下，大小为 31,937 字节。`2026-11-05T15-40-11-863Z-W8fXps` 中的同名会话目录只有 `.ae`。这不是文件被删除；新轮次初始化了新的空目录，导致界面从 ENOENT 变为空。

已通过引擎 `WorkspaceManager.bindSnapshotAsync` 的租约流程将该会话固定绑定原目录，未搬移或覆盖文件。绑定前备份保存在用户引擎状态目录的 `workspace-bindings.before-gomoku-recovery.json`，恢复脚本校验了文件哈希不变及新 manager 在不同默认根下仍解析到原目录。其他会话绑定保持原样。

## 修复

- 开发与显式引擎入口的默认工作目录改为桌面用户配置下的 `engine/state/workspace`；显式环境变量覆盖仍优先，相对路径仍以原运行目录解析。
- 引擎读取尚未初始化的未绑定 scratch 根时返回合法空目录。缺失子目录、失效显式绑定及权限错误继续报错，读取不创建目录。
- Work 初次目录解析失败后允许重试；原始错误放入折叠详情。
- 显式刷新清除当前会话的目标缓存，重新读取权威绑定；旧目标继续保留自己的操作校验。绑定变化后清理旧树和剪贴板，不自动重绑或创建空目录。
- 后台服务使用 360px、随内容决定高度的锚定弹层，默认只显示名称、状态与停止操作，命令和日志按需展开。
- 工作区标签将图标、标题和始终可见的关闭按钮放在同一标签内。最后一个标签也可关闭，并将焦点移回打开工作区按钮。

## 生效边界

恢复后的绑定在下一次服务端解析时生效。已有页面若缓存了旧目标，需要新版刷新逻辑或重新加载页面。持久默认根及首次空目录接口需要重新构建并启动引擎；本次未强制重启用户当前引擎。

`npm run build`（含 node/web typecheck）通过。桌面端分批运行 24 条专项回归，最终全部通过；引擎端 typecheck 与 23 条工作区接口测试通过。未运行仓库全量 E2E。

桌面专项覆盖开发目录稳定性、首次目录失败重试、已有空目录切换到恢复绑定、真实窗口文件操作与会话隔离、单/多标签及唯一文档关闭后重新打开，以及服务弹层尺寸、明暗主题、窄窗口、复制诊断、停止失败和焦点恢复。另验证刷新失败后仍保留树展开、选中、滚动位置，以及隐藏对话停止轮询。已检查服务与标签的明暗截图，真实窗口健康监测无应用错误。

验证中发现关闭最后标签后 keep-alive 面板重新显示为空；已修复为重新显示时恢复记住的标签，保留原失败断言并补充唯一文档关闭场景，最终复跑通过。
