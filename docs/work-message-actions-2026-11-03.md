# 用户消息操作与草稿恢复

## 范围

对照 `D:/web/wuzu-client/src/renderer/src/components/cli/CliMessageBubble.vue` 的六项用户消息操作，补齐 Aether Work；Code 增加缺失的“从此处重新编辑”。本次只改客户端，复用现有引擎接口，不需要重启引擎。

| 操作 | 行为 |
| --- | --- |
| 添加到对话 | 恢复正文、引用与附件，保留当前草稿，不发送、不改历史。Work 重复恢复同一内容不会重复追加。 |
| 重新发起 | 按稳定用户消息 ID 截断目标及后续历史，再发送原指令和附件，保留当前草稿和文件。 |
| 从此处重新编辑 | 截断目标及后续历史，恢复正文、引用与附件，保留最新草稿，不自动发送、不回退文件。 |
| 回退文件 | 回退目标及后续 AI 文件改动；仅全部安全成功后截断历史并恢复原指令。冲突或缺少快照时保留历史并报告。 |
| 复制 | 复制用户可见正文，不带内部引用协议。 |
| 删除本轮 | 只删除目标用户消息及本轮回复，保留前后轮次和文件。 |

Work 操作栏使用单行 28px 图标按钮，悬停或键盘聚焦时显示，触屏常显，支持明暗主题和减少动画设置。四项历史变更有明确确认，任务运行中禁用；复制和添加到对话仍可用。重试进入新流后释放历史操作锁，恢复正常运行中的交互。

异步操作完成后重新读取最新草稿，避免覆盖操作期间输入的内容。Code 重新编辑在慢请求期间禁止发送及再次修改历史，仍允许编辑草稿。切走再返回会话后，旧回调不会回填或误报成功；Work 会重新读取已变化的权威历史。

## 重复原指令的原因与修复

发送会裁剪正文首尾空白，而失败后恢复保留原始空格；旧合并逻辑只做全文严格相等判断，因此肉眼相同的指令可能被再次追加。

新增 `restoreMessageDraft` 按实际发送语义比较正文和引用快照，识别完整草稿或完整段落中已经存在的原指令。重复点击以及刷新后再次恢复保持幂等；不同引用快照、手打的 @ 标签和不同的新指令不会被错误合并。现有用户草稿中已经产生的重复内容不会被自动清理。
