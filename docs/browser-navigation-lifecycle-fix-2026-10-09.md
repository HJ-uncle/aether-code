# 浏览器刷新后控制台与网络记录生命周期修复

日期：2026-10-09。

## 问题

内置浏览器刷新或跳转后，旧页面的控制台消息和网络请求仍显示在调试面板中。网络面板还可能保留旧页的选中请求、正文缓存和第二页位置，导致当前错误页看起来仍然属于之前的页面。

截图中的 `ERR_CONNECTION_REFUSED` 是当前地址对应的本地服务没有监听端口；它与记录没有清理是两个独立问题。刷新后应显示本次加载产生的失败记录，不应继续显示之前页面的请求。

## 修复

- 主文档 `did-start-navigation` 开始时清空控制台和网络采集器，递增文档 `navigationId`，清除旧元素引用。
- 显式刷新使用 `reloadIgnoringCache()`，保证用户点击刷新确实重新执行页面加载流程。
- 网络采集器增加主 frame loader 代际围栏：旧页面晚到的 CDP 事件、异步正文和重定向不会写入新页面；请求 ID 仍保持全局单调，避免旧详情误指向新请求。
- 首个 Document 请求及其重定向链保留在新页面记录中；hash、`pushState` 和 iframe 导航仍视为同一文档，不会清空主文档记录。
- 控制台和网络 UI 在 `navigationId` 变化时立即丢弃旧渲染快照；网络筛选保留，但分页归零、详情取消。

## 验证

构建和类型检查通过：

```powershell
npm run typecheck
npm run build
```

刷新生命周期与采集器回归：**14 passed / 0 failed / 0 skipped**。

现有网络面板和浏览器工具回归：**11 passed / 0 failed / 0 skipped**。

覆盖了真实 Electron 窗口中的刷新、跨文档重定向、失败连接、恢复加载、hash/history、iframe、网络筛选/分页/详情，以及旧正文异步读取隔离。

## 生效

需要使用最新构建并重启客户端。刷新后若仍看到 `ERR_CONNECTION_REFUSED`，请先启动地址栏中对应的本地开发服务；该提示表示端口没有服务响应，并非调试记录残留。
