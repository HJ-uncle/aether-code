# 本地运行空回答故障排查（2026-10-08）

## 本次故障的已确认事实

- 用户发送“帮我做一个五子棋”后，运行 `6eb0f92a-755d-47e8-93ac-f5e682202d4b` 在约 1.6 秒后失败，错误码 `EMPTY_OUTPUT`、结束原因 `empty_output`。
- 本地引擎实际运行的是同级仓库 `D:\dev\ai-agent-engine\dist\main.js`，不是截图中预览页面的编码故障。
- 实际模型为 `deepseek-v4.1-flash`，配置的阿里云地址以 `/apps/anthropic` 结尾，因此选择 Anthropic 协议适配器；提供商标签本身不能代表实际传输协议。
- 对应会话记录只有本轮用户输入，没有本轮助手正文、思考内容或工具调用。不能把会话中此前保留的任务列表当成本轮已经执行工具的证据。
- 该次运行没有可恢复的原始模型响应帧，因而尚不能断言“模型服务确实返回空内容”或“恰好触发下面的解析缺陷”。

## 已复现并修复的缺陷

使用项目实际 Anthropic SDK 和本地 SSE 数据复现，无需生产模型密钥：

1. 网关把完整正文放在 `content_block_start.content_block.text` 时，旧实现只读后续 `text_delta`，丢掉正文。
2. 网关把正文放在 `message_start.message.content` 时，同样被遗漏。
3. `tool_use` 起始帧中已有完整 `input` 时，旧实现丢弃参数并发出 `{}`。
4. 部分思考内容的协议别名没有被归入独立思考通道。

修复在接收起始帧时同步保存快照，避免旧 SDK 随后原地修改对象造成正文重复；最终聚合内容只补缺失部分。工具参数保留完整起始输入或后续 JSON 增量，工具只发出一次。缺少消息结束帧或有效结束原因的流不能报告成功。

## 诊断与界面

- `EMPTY_OUTPUT` 仍然是失败，不自动重复执行整个任务，不把思考内容冒充最终回答。
- 新引擎将空响应的模型、结束原因、片段数、终态标记、正文/思考长度和用量保存到失败助手记录的 `metadata.responseDiagnostics`；日志仅记录这些摘要，不记录原始请求、正文或密钥。
- 空响应也会发送用量事件。仅有思考内容和完全空响应使用不同的中文提示。
- 客户端兼容旧引擎和历史记录中的通用英文提示；具体服务端诊断保持原样。
