# Word、PDF、Excel 生成与预览审查

日期：2026-11-10。范围：继 PPT 调整后，检查三类办公文件的技能说明、生成器、内容检查与 Work 原文件预览。使用隔离夹具，没有运行旧 E2E、导出界面测试或访问生产模型/用户办公文件。

## 结论

格式雷同不只是 skill 的问题。Word/PDF 的模型输入主要是 Markdown、标题和作者，实际页面、字体、边距由生成器决定；Excel 的接口主要是工作表、列和行，当前属于数据表生成器。只修改技能文字不能让这些接口具备任意设计能力。

本次保留一条生成路径，没有添加第二套模板。优先修复内容损坏、不可读布局和预览误导；没有把它们包装成完整的 Office 排版/编辑引擎。

## 发现与处理

| 格式 | 确认的问题 | 本次处理 |
| --- | --- | --- |
| Word | Markdown 显式换行被合并，部分反斜杠残留 | 保留行尾两个空格/未转义反斜杠产生的换行，普通折行仍合并 |
| Word | 空行分隔的同一有序列表重新从 1 编号 | 保持同一列表编号，遇到正文后再开始新列表 |
| Word | 页眉/页脚字段未进入检查告警；预览区段被称为页 | 检查字段并说明未验证分页；Work 标为连续内容预览，区段数量不再充当页数 |
| PDF | 所选字体缺少字形仍报告成功，回读出现 NUL/缺字；TAB 可损坏相邻文字 | 核查实际字体覆盖，尝试可信字体；无法完整显示时明确失败，拒绝不能正确处理的控制符 |
| PDF | 强制显示 Aether 品牌页脚 | 改为普通页码 |
| Excel | 自动换行配固定行高，长文本被裁掉 | create/append 共用内容估宽、换行估高；超过 409 磅行高明确拒绝，不能删字凑布局 |
| Excel | 追加表与新建表的列宽、条纹、类型验证不同 | 共用布局与样式规则，补齐追加表验证及空行样式 |
| Excel | 所有数值强制两位小数，0.001 显示为 0.00 | 普通数值使用 General，实际值、公式、文本编号及百分比规则保持 |
| Excel | Work 预览丢失文件的字体与字号 | 从工作线程保留字体信息，按磅值显示；字体名称/字号有界处理 |

复核期间还修正了 Date 对象的格式优先级，避免非日期列中的已有 Date 被显示为 Excel 序号。相应测试覆盖新建和追加。

## 明确保留的能力边界

- Word：仍是 A4 和默认正文/标题/表格样式，尚无自由图文排版接口。内置 DOCX 预览不计算 Word 自动分页，页码字段可能留空；此次验证不等于在 Word/WPS 中验过所有页面。
- PDF：独立 Markdown 排版，尚无任意原 PDF 正文的保真编辑或 DOCX/PPTX 原版式转换。字体回退要求单一字体覆盖全文，混合中文/特殊符号无法满足时会明确失败，未实现多字体混排。
- Excel：仍以数据表为主，未加入完整报表/仪表盘设计接口。预览不渲染图表、条件格式、数据验证交互；自动估高不是 Excel 原生排版证明。公式重算能力没有扩大。
- 模型自动看图的 `workbench_render` 当前仍只接受 PPTX。三类文件的本次视觉检查由专项 Electron 验收完成，不能据此声称产品已为模型提供三类自动逐页验收。

相关按需技能参考已同步真实能力与限制，没有再添加一套固定模板。开发实例使用固定引擎快照，需要重新启动 `npm run dev` 才会加载此次引擎修改；测试使用的是上述全新构建。
